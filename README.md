# WhatsApp-чат через GREEN-API

Локальное демо-приложение на React и TypeScript для отправки и получения
текстовых сообщений WhatsApp через GREEN-API. WhatsApp используется как
допустимый в тестовом задании вариант, если инстанс MAX недоступен.

## Локальный запуск

Используйте Node.js 22.12 или новее в ветке 22.x, Node.js 24.x либо Node.js 26+.

```sh
npm install
cp .env.example .env.local
npm run dev
```

Откройте локальный URL, который выведет Vite. В GREEN-API подготовьте и
авторизуйте инстанс WhatsApp, затем введите **ID instance** и
**API token instance** на экране подключения. Нажмите **Продолжить**, выберите
**Новый чат** и введите международный номер получателя. Сейчас приложение
принимает российские номера, начинающиеся с `7`, и белорусские — с `375`.
После проверки номера и открытия чата отправьте текст из поля сообщения.

Чтобы проверить весь сценарий, ответьте на сообщение в WhatsApp и убедитесь,
что ответ появился в чате. Чаты, их история и учётные данные сохраняются в
`sessionStorage`: они переживают перезагрузку страницы в той же вкладке, но
удаляются при нажатии **Отключиться** или после завершения сессии браузера.
В левой панели можно открыть сохранённый чат и увидеть его последнее сообщение.

Во время `npm run dev` запросы к GREEN-API проходят через same-origin-прокси
Vite по пути `/green-api`. Укажите в `.env.local` значение `GREEN_API_URL` из
поля `apiUrl` карточки инстанса GREEN-API, например
`https://7107.api.greenapi.com`. После изменения файла перезапустите
`npm run dev`. В репозитории есть только `.env.example`; `.env.local`
игнорируется Git. Не храните `idInstance` и `apiTokenInstance` ни в одном
`.env`-файле.

### Проверка CORS без proxy

По умолчанию приложение использует локальный proxy Vite. Чтобы временно
отправлять запросы напрямую в GREEN-API и проверить CORS, остановите текущий
dev-сервер и запустите его так:

```sh
VITE_GREEN_API_URL=https://7107.api.greenapi.com npm run dev
```

После запуска запросы в DevTools должны идти на `https://7107.api.greenapi.com`,
а не на `localhost`. Этот режим предназначен только для диагностики: URL API
доступен коду в браузере, а CORS-ошибка означает, что для production нужен
серверный proxy.

## Работа с учётными данными

ID инстанса и API-токен хранятся только в `sessionStorage` текущей вкладки и
никогда не попадают в файлы приложения. Не используйте демо на общем или
публичном компьютере: JavaScript, выполняемый на этом origin, может прочитать
`sessionStorage`. Во время локальной разработки браузер отправляет запросы
через прокси Vite; URL запросов с учётными данными всё равно может быть виден
пользователю с доступом к DevTools браузера или локальному сетевому трафику.
Прокси Vite работает только для `npm run dev` и предназначен для локальной
проверки на тестовом инстансе. Production-сборка не включает этот прокси.
В production-приложении запросы GREEN-API следует направлять через серверный
session proxy, который не раскрывает API-учётные данные браузеру.

## Проверки

```sh
npm run test -- --run
npm run build
```

Чтобы диагностировать соединение с GREEN-API без запуска интерфейса, передайте
хост инстанса, ID и токен через переменные окружения:

```sh
GREEN_API_URL=https://your-cluster.api.green-api.com \
GREEN_API_ID=your-id GREEN_API_TOKEN=your-token npm run check:green-api
```

Скрипт вызывает `getStateInstance`, маскирует ID инстанса, не выводит токен и
тело ответа. Он завершится с ненулевым кодом, если хост указан неверно,
учётные данные невалидны или инстанс не авторизован.

Для проверки с реальным GREEN-API нужны авторизованный инстанс WhatsApp и
корректные учётные данные: подключитесь, откройте чат по международному
номеру, отправьте текст, ответьте из WhatsApp и убедитесь, что входящее
сообщение отобразилось. Обновите страницу, чтобы проверить сохранение
выбранного чата и истории в текущей вкладке.
